# T7 — CLI: `spt tasks capture`

[← index](README.md) · source: [full plan](../2026-09-04-nl-task-capture-and-eval-harness.md)

---

**Type:** backend
**Goal:** capture works from a terminal, including with an API key instead of a login.
**Difficulty:** medium
**Depends on:** T6
**Acceptance criteria:**
- [ ] `spt tasks capture <project_id> "<text>"` prints the extracted tasks as a Rich table and
      prompts to confirm; `--yes` skips the prompt; declining creates nothing
- [ ] The CLI sends today's local date as `reference_date`
- [ ] `APIClient` sends `X-API-Key` when `--api-key` or `SPT_API_KEY` is set, falling back to the
      existing bearer-token flow otherwise
- [ ] Low-confidence tasks are visually marked; an unparseable result prints the warning and exits 0
- [ ] Output strings go through `t()` and exist in both `app/locales/*.json` used by the CLI
**Files in scope:** `app/cli/commands/tasks.py`, `app/cli/http.py`, `app/cli/config.py`,
`app/cli/output.py`, `tests/test_cli_commands.py`, `tests/test_cli_http.py`.
**Constraints:** Typer + Rich as in the existing commands; no new CLI dependency. An API key must
never be written to the CLI config file on disk — read it from the flag or the environment only.
**Verification:** `uv run pytest tests/test_cli_commands.py tests/test_cli_http.py`; manual run
against a local server with both auth modes.
**Out of scope:** interactive editing of extracted tasks before confirming.
