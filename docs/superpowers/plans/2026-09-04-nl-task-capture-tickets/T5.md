# T5 — `POST …/tasks/capture/confirm` — create the tasks

[← index](README.md) · source: [full plan](../2026-09-04-nl-task-capture-and-eval-harness.md)

---

**Type:** backend
**Goal:** a reviewed set of extracted tasks becomes real tasks, through the same code path as any
other task creation.
**Difficulty:** hard — writes user data, all-or-nothing transaction semantics, RBAC and demo guard.
**Depends on:** T4
**Acceptance criteria:**
- [ ] Creation goes through the existing `task_service.create_task` / `create_task_for_project`, so
      status defaults, `position`, `StatusHistory` and the demo guard are inherited, not reimplemented
- [ ] Tasks with a `story_id` are created under that story; tasks without one land in the project's
      default Backlog story, matching current behaviour
- [ ] A `story_id`, `assignee_id` or `sprint_id` that does not belong to this project → 422 and
      **zero** tasks created; asserted by counting rows after the failed call
- [ ] Demo accounts get 403 `DEMO_ACCOUNT`; non-members 403; unknown project 404 — before any write
- [ ] Batch is capped at 20 tasks; 201 returns the created tasks in request order using the existing
      `TaskResponse` shape
- [ ] The request body accepts exactly the contract's fields — no `status`, no free-form extras
      (`extra="forbid"`)
**API contract:** *identical to the block in T4 — copy it verbatim.*
**Files in scope:** `app/api/routes/tasks.py`, `app/api/schemas/capture.py`,
`app/api/services/capture_service.py` (confirm path), `tests/test_api_capture.py`.
**Constraints:**
- One transaction for the batch. The existing services each `commit()`; reconcile this deliberately
  (flush-per-task then a single commit, or an explicit nested transaction) and say which in the PR —
  a partial write here is the worst failure mode in the whole feature.
- No new model, no migration (decision D1: extraction runs are not persisted).
- The endpoint calls no LLM.
**Verification:** `uv run pytest tests/test_api_capture.py` including the all-or-nothing rollback
test; then by hand, a `capture` call followed by feeding its output straight into `confirm`.
**Out of scope:** API-key auth (T6); UI; retry/undo semantics.
